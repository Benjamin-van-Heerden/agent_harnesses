# Work Log - Python Installer and Harness Auto-Update

## Overarching Goals

Replace the Bash-specific coding harness installer with a Python-first update
path, make optional docs non-interactive and collision-resistant, and add an
automatic harness update mechanism that runs in the correct onboard sequence.

## What Was Accomplished

- Ran onboarding and loaded the project context.
- Updated optional docs handling around the new `coding_*` document names:
  - removed the interactive optional-doc picker from setup;
  - kept default installation for `coding_general` and `coding_testing`;
  - made `--update` refresh already-installed optional docs by matching names.
- Reworked the coding harness `AGENTS.md` concepts/commands section:
  - removed the redundant core-concepts list;
  - scoped commands under Specs, Tasks, Todos, Work Logs, Memories, Documents,
    and Repair Commands;
  - moved `sync issues` into repair-only guidance.
- Replaced `coding/setup.sh` with a stdlib-only `coding/setup.py` foundation:
  - supports local template use and remote GitHub archive fetching;
  - preserves project-owned state while replacing managed runtime files;
  - manages config, AGENTS block updates, CLAUDE compatibility, optional docs,
    branch validation/creation, and `last_updated_at`;
  - changed update assumptions so `--update` must run from configured `dev`;
  - changed initialization branch sequencing to require configured `main`,
    create missing `test` from `main`, then create missing `dev` from `test`.
- Added `[harness]` config support to the coding harness:
  - `last_updated_at`;
  - `update_interval_days`.
- Added onboard auto-update support:
  - onboarding still checks that the repo is clean first;
  - stale harness state triggers remote `coding/setup.py --update` through
    `sys.executable`, without Bash, curl, or process substitution;
  - if the update dirties the repo, it commits and pushes with
    `harness updated YYYYMMDD`;
  - onboard re-execs afterward so context is generated by the refreshed harness;
  - `AGENT_CORE_SKIP_AUTO_UPDATE=1` bypasses the mechanism for recovery.
- Added a convenience update entrypoint:
  - `coding/.agent_core/harness/update.py` in the template;
  - `.agent_core/harness/update.py` and installed `auto_update.py` locally so
    `python -B .agent_core/harness/update.py --help` works immediately.
- Updated setup-related tests and docs from `setup.sh` to `setup.py`.
- Verified focused static checks:
  - `python -B -m py_compile` on changed setup/update/onboard/config modules;
  - `uv run ty check` on changed setup/update/onboard/config modules;
  - `git diff --check`;
  - `python -B coding/setup.py docs list`;
  - `python -B .agent_core/harness/update.py --help`.
- Did not run the actual remote updater because it can download remote code,
  mutate the repo, commit, and push.
